ArchFlow in Docker now has accounts and logins. New since [v0.8.1](https://github.com/cyryllo/ArchFlow/releases/tag/v0.8.1).

> **Before you update.** A `compose.yml` from before this release keeps working without logins. **The new `compose.yml` turns logins on** (`AUTH_MODE=local`). Right after starting it, open ArchFlow and create the administrator account: until then, anyone who reaches the address could do it. Your diagrams stay as they are; they're visible to every logged-in user. To stay without logins, set `AUTH_MODE=none`.

### 🔐 Accounts and logins

- **Logging in** with e-mail and password. A login lasts 30 days. Changing a password logs out other browsers, and repeated failed attempts are slowed down.
- **The first administrator** is created on the first visit, or from `ADMIN_EMAIL` and `ADMIN_PASSWORD`.
- **Three roles:** *administrator* (everything, plus users and settings), *editor* (creates, changes and deletes diagrams) and *viewer* (only opens them, in a read-only editor). Every logged-in user sees all diagrams. Each diagram records who created it and who changed it last, shown in *My diagrams*.
- **Admin panel** (☰ → *Users and settings*):
  - add users, with a temporary password shown once and changed at the first login;
  - change roles, reset passwords, and disable or delete users;
  - ArchFlow always keeps one active administrator.
- **Public access** (a setting in the admin panel): people who aren't logged in can open ArchFlow and design, but save only in their browser or to a file, never to the server.
- Everything works in all 10 interface languages.

### 🤖 Personal tokens for AI assistants

- **Each user creates their own tokens** in *Account*: read-only or read-and-change, with an optional expiry date. ArchFlow shows the token once, together with a ready `claude mcp add …` command for Claude Code.
- **A token acts with its owner's rights.** A viewer's token can't change anything, and a disabled user's tokens stop working.
- **The administrator decides who may use the API and MCP** (per user, or for everyone), sees all tokens and can revoke any of them.
- **The MCP server in Docker uses these tokens** when logins are on, so it no longer needs a separate setting. `MCP_TOKEN` stays only for ArchFlow without logins.

### 🛡️ Security fix

- A diagram id in an API request could reach files outside the diagrams folder. The server now accepts only plain diagram names.

### 🐳 Docker

~~~bash
docker compose pull
docker compose up -d
~~~

Your diagrams in `./diagrams` are kept, and the accounts are stored next to them (`.archflow/auth.json`). To turn logins on with an older `compose.yml`, download the new one or add `- AUTH_MODE=${AUTH_MODE:-local}` under `environment`.
